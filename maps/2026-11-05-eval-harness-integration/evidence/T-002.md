# T-002 — Can Harbor run a paired with/without-skill experiment and report lift?

**Answer: yes, with a small comparison script. Harbor supplies the two arms
(`--skill` / `environment.skills_dir`) and per-job metrics, but it has no native
"lift" report.**

## Evidence

### Skill injection

`https://docs.harborframework.com/jobs/skills`:

> "Skills let you inject context files, prompts, rules, and reference
> documentation into agent trials. A skill is a directory containing a
> `SKILL.md` file."

For each trial Harbor uploads each skill to `/runtime/skills/<skill-name>` (or
`environment.skills_dir`), then passes the directory to the agent integration as
`skills_dir`. `--skill <path>` and `--skill <org/repo>@<ref>` are the CLI
surface; `--skill` can be repeated. Provenance (name, source, digest, git SHA)
is recorded in the job lock.

`https://docs.harborframework.com/tasks/skills` adds task-level skills:
`environment.skills_dir = "/skills"` with a `COPY skills/ /skills/` in the task
Dockerfile. Job-provided skills are uploaded into the same directory.

So the two arms are:

- **with-skill:** `harbor run ... --skill <tackle-skill>`
- **without-skill:** the same command without `--skill`

### Metrics

`https://docs.harborframework.com/datasets/metrics` documents `metric.py`,
which receives the job's rewards JSONL and writes an aggregate JSON. It is
per-job; it does not compare two jobs.

`https://docs.harborframework.com/results/view-job-results` documents
`harbor view jobs`: a local viewer with job/trial browsing and `Shift`+arrow to
switch jobs. It is an inspection tool, not a lift calculation.

### What is missing

No documented "paired run" or "lift" primitive. A small script must read the two
jobs' `results.json` / rewards JSONL and compute the paired delta (and variance).
That is a post-processing script, not a second eval framework.

## Assessment

- **Proven:** `--skill` / `skills_dir`; provenance; per-job `metric.py`; job
  viewer.
- **Inferred:** two jobs are the intended way to compare conditions.
- **Unverified:** whether a custom `metric.py` can see task IDs (the example
  input is rewards only), so a separate script is the safe design.

## Effort

Low. Run two jobs, then a ~100-line script that pairs trials by task ID and
reports mean delta, variance, and per-task wins/losses. The bigger job is
mapping a Tackle prompt package into `skills_dir` (T-005).
