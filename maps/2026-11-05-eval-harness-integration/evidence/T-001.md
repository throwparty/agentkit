# T-001 — Can BenchFlow run SWE-bench through its Harbor inbound adapter?

**Answer: not natively. BenchFlow has no SWE-bench adapter; it can import
Harbor-format SWE-bench tasks, but official-equivalent scoring is unproven and
adoption is a parity-gated conversion, not a flag.**

## Evidence

### BenchFlow's benchmark roster

`https://docs.benchflow.ai/running-benchmarks` lists the adapted benchmarks:
Harvey LAB, ProgramBench, SkillsBench; environment-plane: ClawsBench,
chi-bench. SWE-bench is not among them.

The same page documents the only foreign-benchmark path:

> "BenchFlow runs benchmarks authored in other formats without converting them
> first. An **inbound adapter** translates a foreign task directory into
> BenchFlow-native shape... | Harbor | `task.toml` | `HarborAdapter`"

So a SWE-bench task in Harbor format is importable through `HarborAdapter`.
A native SWE-bench dataset is not.

### BenchFlow's adoption path

`https://docs.benchflow.ai/benchmark-adoption` documents `bench eval adopt`:
`init` scaffolds `benchmarks/<name>/`, `convert` drives a codex conversion to
Harbor-format tasks, and `verify` runs a parity gate. The verdicts are
`parity-confirmed`, `parity-divergent`, and `insufficient-evidence`. A fresh
benchmark is `insufficient-evidence` and exits non-zero.

This is the correct path if BenchFlow is chosen for SWE-bench: adopt the
benchmark and prove parity, rather than assuming Harbor-format import is
equivalent.

### Do the Harbor-format tasks carry the official test patch?

The Hugging Face dataset `DCAgent/swebench-verified` is described as
"SWE-bench Verified (500 tasks) via Harbor adapter"; its commit message says
"SWE-bench test patch". Harbor also ships an adapter for SWE-bench Pro
(`adapters/swebenchpro/README.md`). That is evidence the tasks carry the
benchmark's test patch, not proof that the pass rule (FAIL_TO_PASS /
PASS_TO_PASS) is identical to the official harness.

## Assessment

- **Proven:** no native SWE-bench adapter; Harbor-format import exists; an
  adoption + parity workflow exists.
- **Inferred:** BenchFlow can run the Harbor-format SWE-bench tasks through
  `HarborAdapter` and its ACP runner.
- **Unverified:** official-equivalent resolved rates; whether `HarborAdapter`
  preserves every field the SWE-bench verifier needs; whether the Harbor-format
  task's `tests/test.sh` applies the official test patch and evaluates the
  official FAIL_TO_PASS/PASS_TO_PASS sets.

## Effort

Medium. Running a Harbor-format task is low effort; proving parity is the work:
a small overlap set through BenchFlow and the official SWE-bench harness, plus
the `bench eval adopt verify` gate. This is why BenchFlow is not the first
choice when SWE-bench is the priority.
