# T-010 — Which SWE-bench variant and subset give a first signal?

**Answer: start with a 25-instance subset of SWE-bench Verified, run through
Harbor's dataset, at 3 trials; scale to 100 then 500 only after the baseline is
stable. The first subset is for a signal, not a leaderboard.**

## Evidence

- SWE-bench variants: Lite (300), Verified (500 human-validated), full
  (2,294), Pro (enterprise, 731). `https://www.swebench.com/` and the
  `swebench` harness docs list Lite, Verified, Multimodal.
- Official harness resources: at least 120 GB disk, 16 GB RAM, 8+ cores
  recommended, x86_64. SWE-bench Lite takes ~30–50 minutes at `cache_level=env`
  (16-core/12 workers ~30 min; 8-core/6 workers ~50 min).
  `https://www.swebench.com/SWE-bench/reference/harness/`
- Harbor Hub publishes `swe-bench/swe-bench-verified` and
  `scale-ai/swe-bench-pro`; Harbor also has a SWE-bench Pro adapter
  (`adapters/swebenchpro/`).
- The official harness caches by `run_id` + `instance_id` and ignores patch
  content, so every new patch needs a new `run_id`.

## Why 25 instances

- 25 × 3 trials = 75 rollouts. At ~10–30 minutes per rollout (model-dependent),
  that is a day-scale first run, not a week-scale one.
- A 25-instance subset is enough to catch wiring failures, crashes, and gross
  capability gaps. It is not enough to rank models or claim a percentage.
- Use a fixed, committed instance list (IDs in a file) so later runs are
  comparable. Do not let the subset drift.

## Assessment

- **Proven:** variant sizes; resource envelope; Harbor datasets exist.
- **Unverified:** per-instance wall-clock for Tackle; image cache size for the
  Harbor dataset; whether the 25-instance subset is representative.

## Open choices

- Verified vs Pro for the first run. Verified is the public comparison point;
  Pro is harder and more enterprise-like. Start with Verified.
- Whether to use Harbor's dataset or the official harness. Harbor gives
  trajectories; the official harness gives the canonical score. T-014 decides
  whether they agree.
