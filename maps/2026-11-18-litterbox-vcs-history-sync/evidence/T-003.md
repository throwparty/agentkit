# T-003 — jj conflict paths, sides, and manual resolution

**Question:** How does jj expose conflict paths and their base/ours/theirs sides, and does editing the materialised markers resolve the conflict or is `jj resolve` required?

**Answer:** Paths come from `jj resolve --list` (or the warning in `jj status`/`jj log`); the sides come from `jj diff --from <base> --to <ours|theirs> --git -- <path>`, where the sides are the merge commit's parents and the base is their merge base. The conflict is materialised in the working-copy commit, using jj's `%%%%%%%`/`\\\\\\\`/`+++++++` marker format. Editing the file and running any jj command (for example `jj status`) snapshots the working-copy commit and clears the conflict; `jj resolve` is the merge-tool entry point, not a requirement for a manual edit. In this probe `jj new ours theirs` made the merge commit the working copy, so the edit resolved the conflicted commit in place. If the conflict is a parent, `jj squash` or `jj amend` moves the resolution into it.

## Reproduction

`probe.sh` builds a Git repo with `base`, `ours` and `theirs`, converts it to a colocated jj repo, merges with `jj new ours theirs`, prints the status, log, conflict list, materialised markers and both side diffs, then edits the file and checks the result. Run:

```sh
bash maps/2026-11-18-litterbox-vcs-history-sync/evidence/T-003/probe.sh
```

Raw output: [`output.txt`](output.txt).

Key observations:

- `jj resolve --list` prints `file.txt    2-sided conflict`.
- The materialised file uses jj's marker style, including `%%%%%%% diff from: ... base` and `\\\\\\\ to: ... ours`.
- `jj diff --from <base> --to ours --git -- file.txt` and `--to theirs` give the two changes cleanly, without parsing the markers.
- After `printf 'APPLE\nGRAPEFRUIT\nORANGE\n' > file.txt`, `jj status` reports the working-copy change and `jj resolve --list` says `No conflicts found at this revision`; `jj log` no longer marks the commit `(conflict)`.

**Implication for MCP:** `sandbox-conflict` can return the sides by running the two `jj diff` commands against the merge commit's parents. `sandbox-resolve` can rely on the agent editing the workspace and jj snapshotting the edit, then verify with `jj resolve --list`; it does not need to run a merge tool.
