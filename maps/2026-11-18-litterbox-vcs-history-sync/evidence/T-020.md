# T-020 — retention of a dropped sandbox tip

**Question:** When adoption drops a sandbox tip, how is it kept?

**Answer:** In the branch reflog. Adoption reports the old tip once and names the reflog. No new ref and no record field.

## Why

Every tip the shared branch has held is in its reflog, because the sandbox's snapshots were branch tips until the user rewrote them. The full sequence exists there for the reflog lifetime: about 30 days for entries that become unreachable, 90 days for reachable ones, plus the object grace period. Under `direct` the user's repository logs branches by default. Under `remote` Litterbox sets `core.logAllRefUpdates=always` on the bare store it owns.

One field on the record would keep only the most recent drop. A ref per drop would grow the namespace and need a prune policy. The reflog answers "what was on this branch before" with the tool a Git user already knows.

## Reporting

`status` names the branch reflog and the `git reflog show` command. The adoption result names the tip it dropped. Recovery is `git branch <name> <sha>`.
