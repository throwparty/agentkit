# T-002 — masking `.jj` on a bound jj workspace

**Question:** Can a jj workspace be bind-mounted into a sandbox with `.jj` masked on bubblewrap, Docker and Seatbelt?

**Answer:** Bubblewrap and Docker can hide the **contents** of `.jj` on this Linux host; the directory entry remains as an empty mountpoint. Bubblewrap uses `--tmpfs <workspace>/.jj` over the bound workspace; Docker uses an empty volume at `/workspace/.jj`. In both cases the workspace files are present and `.jj` is empty.

The probe proves the mountpoint, not confinement. It runs bubblewrap with `--ro-bind / /` so the sandbox can find a shell, and that root bind also leaves the probe's bridge and bare store readable from inside. Confinement is a property of the production view instead, and is a code fact rather than a probe result: `crates/agentkit-litterbox/src/backends/bubblewrap/view.rs` binds only `/proc`, `/dev`, a tmpfs `/tmp`, a tmpfs `/home`, empty `/bin`, `/usr` and `/usr/bin`, the pinned tool paths read-only, and the workspace. Its unit test requires exactly one `--bind` (the workspace, the only writable host tree) and one `--ro-bind`. A confined-view probe that checks the bridge and the bare store are unreachable is still owed; until then the confinement claim rests on the view construction, not on this probe.

If the directory name itself must be absent, an overlay/whiteout or a filtered view is required; an empty mountpoint is not absence. Seatbelt is macOS-only and was not probed here, so it is unproven rather than assumed.

## Reproduction

`probe.sh` creates a non-colocated jj bridge and one workspace, then runs bubblewrap and Docker with the workspace bound and `.jj` masked. Run:

```sh
bash maps/2026-11-18-litterbox-vcs-history-sync/evidence/T-002/probe.sh
```

Raw output: [`output.txt`](output.txt).

Key observations:

- `bwrap --ro-bind / / --bind <ws> <ws> --tmpfs <ws>/.jj --chdir <ws>` sees `README.md` and sees `.jj` as an empty directory. The root bind keeps the probe's own bridge and store reachable, so this result covers the workspace metadata only.
- `docker run -v <ws>:/workspace -v <empty>:/workspace/.jj <image> ...` has the same result.
- Seatbelt is recorded as `unprobed: macOS-only; this host is Linux`.

**Implication:** `Bound` can hide the workspace's VCS metadata on bubblewrap and Docker by masking contents. Whether anything outside the workspace is reachable depends on the backend's view, which this probe does not exercise: the production bubblewrap view binds no root and exposes only the workspace and pinned tools. The capability report must distinguish “contents hidden” from “path absent”; only the former is proved here. A backend that cannot mask at all must refuse `Bound` for a VCS whose metadata lives in the workspace.
