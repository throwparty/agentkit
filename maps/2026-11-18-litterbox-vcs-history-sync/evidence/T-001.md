# T-001 — jj repository backed by a bare Git repository, multiple workspaces

**Question:** Can a jj repository be backed by a bare Git repository and host multiple jj workspaces, one per sandbox?

**Answer:** Yes, with two caveats. `jj git init --no-colocate --git-repo=<bare> <bridge>` creates a non-colocated jj repo whose store is the bare Git repo. `jj workspace add <path> --name sandbox-N` adds a workspace per sandbox, and every workspace shares the same repository. The bridge is **not** workspace-less: jj creates an initial `default` workspace at the bridge directory (`.jj` plus a checkout), which Litterbox can leave unused. Changes in a workspace are anonymous commits until a bookmark is created; `jj git export` then publishes the bookmark to the bare Git repo as `refs/heads/<name>`. Without a bookmark, the bare repo only receives `refs/jj/keep/*` for GC protection and the branch does not move.

## Reproduction

`probe.sh` creates a bare Git repo, seeds it, creates the jj bridge, adds two workspaces, commits a change in each, creates `litterbox/sandbox-1` and `litterbox/sandbox-2` bookmarks, and exports. Run:

```sh
bash maps/2026-11-18-litterbox-vcs-history-sync/evidence/T-001/probe.sh
```

Raw output: [`output.txt`](output.txt).

Key observations from the run:

- `jj workspace list` reports `default`, `sandbox-1` and `sandbox-2`, all sharing one repo.
- `jj log` from the bridge shows both workspace changes.
- Before bookmarks, the bare Git repo has `refs/heads/main` and many `refs/jj/keep/*` entries; `jj git export` reports `Nothing changed`.
- After `jj bookmark create litterbox/sandbox-1 -r @-` and `jj bookmark create litterbox/sandbox-2 -r @-`, `jj git export` writes `refs/heads/litterbox/sandbox-1` and `refs/heads/litterbox/sandbox-2` to the bare repo.
- The bridge directory contains `.jj` and `README.md`; the initial workspace is a real checkout, not a bare layout.

**Implication:** the jj bridge is a jj repo with a control workspace. Litterbox must create or move a bookmark for each sandbox branch and run `jj git export` after a snapshot for the bare Git view to move. The workspace itself needs no `.git`.
