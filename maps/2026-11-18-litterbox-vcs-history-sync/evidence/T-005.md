# T-005 — refs/notes for conflicted Git commits

**Question:** Can a conflicted Git commit be marked with refs/notes so Litterbox can compute inherited conflict for descendants, and what is the ref/note layout?

**Answer:** Technically yes, but the pattern has no ecosystem support and should not be used to emulate late conflict resolution. `refs/notes/litterbox/conflicts` can map a commit to `state/merge/base/ours/theirs`; `git rev-list` plus notes finds the nearest marked ancestor; notes need an explicit `+refs/notes/*:refs/notes/*` fetch. But the tools that use notes use them for **metadata about a commit**, not for the commit's conflict state: git-appraise (archived) stores review requests and comments under `refs/notes/devtools/*`, Gerrit's `reviewnotes` plugin uses `refs/notes/review`, and attribution tools attach provenance. No tool was found that stores a conflicted commit, an unresolved merge, or a late-resolution workflow in notes. Git's own merge/rebase/checkout will treat the commit as resolved content; jj uses `jj:trees`; `git-imerge` uses refs and commits.

**Design consequence:** reject `Deferred` for Git. Git uses `Blocking`; jj uses `Native`. The `ConflictModel` is `Native | Blocking`. Notes are not part of the Litterbox design.

## Reproduction

`probe.sh` demonstrates the mechanism: a conflicted `merge-tree` commit, a note under `refs/notes/litterbox/conflicts`, a child and grandchild, an ancestor walk, and a clone with and without the notes refspec. Run:

```sh
bash maps/2026-11-18-litterbox-vcs-history-sync/evidence/T-005/probe.sh
```

Raw output: [`output.txt`](output.txt).

Key observations:

- The note is `state=conflicted merge=1 base=... ours=... theirs=...`.
- `git rev-list <grandchild>` contains the conflicted commit; checking each revision's note finds it.
- A plain clone does not have the note; the explicit notes refspec does.

## Research

- [git-appraise](https://github.com/google/git-appraise) — archived; review data under `refs/notes/devtools/reviews`, `.../discuss`, `.../ci`. Metadata about commits, not conflict state.
- [Gerrit reviewnotes](https://gerrit.googlesource.com/plugins/reviewnotes/) — `refs/notes/review` for code review information.
- [git-imerge](https://github.com/mhagger/git-imerge) — incremental merge using refs and commits; no notes.
- Jujutsu — conflicts are an ordered list of trees in the commit, stored in `jj:trees` for the Git backend; no notes.
- No tool found that uses notes for divergent histories, conflicted commits, or deferred resolution.
