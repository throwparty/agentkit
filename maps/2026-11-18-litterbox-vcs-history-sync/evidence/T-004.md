# T-004 — `git merge-tree --write-tree --merge-base` conflict tree

**Question:** Does `git merge-tree --write-tree --merge-base=<tree>` produce a usable conflict tree and exit status, and can that tree be committed and annotated as a conflicted commit?

**Answer:** Yes, with a constraint: the tree is usable and committable, but the commit is ordinary. The command exits `1` on conflict, prints the conflicted tree OID on the first stdout line, then the index-stage entries and conflict messages. The tree materialises the conflicted file as a normal blob containing `<<<<<<<` / `=======` / `>>>>>>>` markers. `git commit-tree <tree> -p <ours> -p <theirs>` produces a normal two-parent commit; Git retains no index stages or conflict metadata. A `Deferred` model therefore needs Litterbox-owned refs/notes, not a Git-native conflicted commit.

## Reproduction

`probe.sh` in this directory creates a temporary repository under `work/`, builds `base`, `ours` and `theirs`, runs `git merge-tree`, inspects the tree, and commits it. Run:

```sh
bash maps/2026-11-18-litterbox-vcs-history-sync/evidence/T-004/probe.sh
```
