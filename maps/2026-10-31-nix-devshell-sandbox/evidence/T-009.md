# T-009: session isolation with cgroup lifecycle

**Question.** Can lifecycle use `--new-session` with cgroup v2 freeze on systemd hosts and process-group signalling elsewhere?

**Method.** `adrs/2026-10-31-linux-bwrap-lifecycle/poc/lifecycle-cgroup.sh` and `poc/all.sh` on NixOS, kernel 7.2.12, systemd user manager, bwrap 0.12.0.

**Observation.** The harness ran under `systemd-run --user --scope --unit=lbx-<pid>` with `--new-session`. `systemctl --user freeze` stopped the loop writing to `/src/loop`; two samples taken after the freeze completed were unchanged at 12 bytes. `systemctl --user thaw` resumed it to 20. `unfreeze` is not a systemd verb; `thaw` is, and a frozen unit cannot be stopped, so cleanup thaws first. With `XDG_RUNTIME_DIR=/nonexistent` the launcher exits 69 and the copied process-group `lifecycle.sh` freezes at 10, resumes to 20 and kills cleanly.

A user manager without cgroup delegation is not detected up front: the scope start fails and the probe exits non-zero, so the caller selects the fallback by hand. EC-002 records that as accepted and unverified.

**Conclusion.** Yes on systemd hosts with cgroup delegation. The fallback keeps process-group lifecycle and gives up session isolation. A delegation-absent host relies on that fallback, which is tested but not selected automatically.
