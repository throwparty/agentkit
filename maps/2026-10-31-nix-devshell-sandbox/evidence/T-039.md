# T-039: does bwrap's status document mean the sandbox is usable?

**Question.** When bwrap reports the child pid and the namespace inodes on its
status descriptor, has it finished building the view, or does setup continue
afterwards?

**Method.** Time three moments for a small view and for the 1779-path view from
T-035. The first is when the status document is readable. The second is when the
view is built, which is when no `/oldroot` mount remains and the workspace is
mounted. The third is a joined command. Reproduce with
`evidence/T-033-039-probes.sh`.

**Observation.**

```
small view  (3 binds):    status 26ms, view usable 60ms,   command ok
large view  (1779 binds): status 43ms, view usable 4246ms, command ok
```

A join attempted 300ms after the status document of the large view failed with
`failed to execute /run/current-system/sw/bin/sh: No such file or directory`,
and the mount table at that moment still showed the old root at `/oldroot`.

**Conclusion.** No. bwrap writes the status document early in setup. The view is
not usable until it has finished, and the gap grows with the bind count: 34ms
for a three-bind view and 4.2s for 1779 binds.

Two consequences for the backend. create must not treat the status document as
readiness, and it must not run a provisioning step or return a record until the
view is built. The check that does not depend on bwrap internals is the view
itself: wait until every recorded mount is present with its recorded access,
which is the same check a later join makes. The create budget must cover setup,
not just the steps.
