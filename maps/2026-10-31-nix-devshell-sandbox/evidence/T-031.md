# T-031: who writes the prepared environment into the record?

**Question.** Who writes the prepared environment and store view into the
sandbox record, and in what shape?

**Method.** Read the record type, the backend methods that receive it, the
metadata store, and the Docker payload.

## Observation

`crates/agentkit-litterbox/src/sandbox/contract.rs:18-25`:

```rust
pub struct SandboxRecord {
    pub name: String,
    pub backend: String,
    pub project_slug: String,
    /// Backend-owned addressing data.
    pub data: toml::Value,
}
```

`Backend::create` returns the record at `contract.rs:443-448`. `exec` receives
`&SandboxRecord` at `:450-457`, `inspect` at `:473-480`, and `delete` at `:478`.
The backend therefore reads its own payload on every later operation.

`crates/agentkit-litterbox/src/metadata_store.rs:59-63` places the record at
`agentkit_common::data_dir("litterbox")/metadata/<project_slug>/<name>.toml`.
`store_value_in` at `:99-140` creates the directory with mode 0700, writes the
file with mode 0600, and renames it into place.

Docker's payload at `backends/docker/backend.rs:65-70` is:

```rust
struct DockerData {
    container: String,
    forwards: Vec<Forward>,
    environment: Provenance,
}
```

The values live in the container. `create` builds that payload at
`backend.rs:482-492` and returns the record. A native backend has no container
holding the environment, so its payload must also carry the values. The
contract already has the type for them:
`crates/agentkit-litterbox/src/sandbox/environment.rs:87-94` is `Environment {
variables, provenance, workspace }`.

## Conclusion

The backend writes the payload. The contract requires that a later command sees
the same environment and mounts, and that `inspect` reports provenance. It does
not define the payload's shape, and the core never writes the file.

The alternative, a core-owned schema keyed by kind and identity, is rejected for
three reasons. It contradicts T-027, because a kind outside the contract has no
closed type to key the schema with. It duplicates what `CreateRequest` already
carries into `create`. And it forces every backend to parse a format the core
invented.

The payload is not the devShell's realisation. Nix owns the output path and
keeps it alive through a GC root. The record stores what entering the shell
produced, so that `exec` in another process does not have to enter it again.
Re-entering would run the hook once per command, cost 470 to 610 ms per command,
and let a flake change reach a running sandbox, which EC-010 forbids.
