# T-047. Can the helper be environment-transparent?

Answer: yes. A helper that applies the profile and execs with the
inherited environment passes every contributed variable through unchanged. The
prototype's allowlist is unnecessary and wrong: it drops most of a real
devShell environment. Withholding values that name ungranted paths stays the
backend's job; the helper does not filter.

Host: macOS 27.2.1 (26B131), arm64. Probed 2026-11-14.

## Reproduce

```
env -i PATH=/usr/bin:/bin HOME=<ws> TMPDIR=<ws>/tmp PWD=<ws> \
  RUSTFLAGS=-Cdebuginfo=2 GITHUB_TOKEN=hunter2 \
  PKG_CONFIG_PATH=/opt/t047-secret/lib SPACED='a b "c"' \
  ./helper --workspace <ws> -- /usr/bin/env
```

`T-043-helper.c` is the T-043 helper: it execs with `environ` untouched.

## Results

Transparent helper, sorted output:

```
GITHUB_TOKEN=hunter2
HOME=<ws>
PATH=/usr/bin:/bin
PKG_CONFIG_PATH=/opt/t047-secret/lib
PWD=<ws>
RUSTFLAGS=-Cdebuginfo=2
SPACED=a b "c"
TMPDIR=<ws>/tmp
```

Prototype helper (`sandbox-custom`, same inputs):

```
HOME=<ws>
PATH=/usr/bin:/bin
TMPDIR=<ws>/tmp
```

`RUSTFLAGS`, `GITHUB_TOKEN`, `PKG_CONFIG_PATH`, `SPACED` and `PWD` are dropped.
That is five of eight variables, including the build flags and the credential
the workload was given. Rebasing workspace-rooted values and withholding
ungranted paths cannot be done by an allowlist.

## A variable is inert

```
$ cat <probes>/t047-secret/lib        # outside the sandbox
secret
$ env -i ... PKG_CONFIG_PATH=<probes>/t047-secret/lib \
    ./helper --workspace <ws> -- /bin/cat <probes>/t047-secret/lib
cat: <probes>/t047-secret/lib: Operation not permitted
```

The variable did not widen the profile. So there is no security reason to
filter the environment in the helper; passing a value through grants nothing.

## Consequence for D

- The helper takes the environment from the backend, unchanged. It does not
  env_clear, reorder, or substitute.
- The backend owns the two transformations the Linux backend already does:
  withhold a variable whose value names a path that is neither the workspace nor
  a granted mount (`bubblewrap/environment.rs::value_is_granted`), and rebase
  workspace-rooted values with `Contributions::environment_for`.
- `HOME`, `TMPDIR` and `PWD` are backend-owned, as on Linux; with no steps there
  is no `PATH`, and the backend does not invent one.
