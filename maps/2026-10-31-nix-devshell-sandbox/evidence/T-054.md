# T-054. Can SBPL name paths through parameters instead of inline escaping?

Answer: yes. `sandbox_init_with_parameters` accepts paths as parameter values,
so the profile text holds placeholders and no path is ever escaped into SBPL.
Paths containing `"` or `(` work unchanged, and the apply ceiling rises from
about 1,010 inline paths to above 2,600. Cost grows with the rule count, so the
64-path collapse still stands: at 64 parameters the cost matches inline, at 238
it is about twice inline, and at 1,779 it is unusable.

Host: macOS 27.2.1 (26B131), arm64. Probed 2026-11-14.

## Reproduce

Sources beside this file: `T-054-params.c` reads one workspace and one file
through `(subpath (param "WS"))` and `(literal (param "FILE"))`; `T-054-count.c`
applies a profile with N `(subpath (param "P<n>"))` rules and a distinct 45-byte
value for each.

```
mkdir -p build
cc -O1 -o build/params T-054-params.c
cc -O1 -o build/count  T-054-count.c
```

## Parameters work, including awkward paths

```
$ build/params <ws>/p-ws <ws>/p-ws/a"b(c)/f /bin/cat <ws>/p-ws/a"b(c)/f
odd-name
exit=0
```

The path contains a double quote and parentheses and is passed as a parameter
value. Nothing in the profile text is escaped, because the path is not in the
profile text.

## The ceiling

| N distinct parameters | Profile bytes | Result |
|---:|---:|---|
| 8 | 461 | applies |
| 64 | 1,915 | applies |
| 238 | 6,577 | applies |
| 1,000 | 27,151 | applies |
| 1,779 | 48,963 | applies |
| 2,000 | 55,151 | applies |
| 2,600 | 71,951 | applies |
| 3,000 | 83,151 | `compilation failed` |

The failing limit is on the profile text or the compiled object, not on the
number of parameters as such. The exact boundary between 2,600 and 3,000 was
not found because the collapse makes it unreachable.

## Cost

Single runs with `/usr/bin/time`, including process start:

| N | Params | Inline (T-044) |
|---:|---:|---:|
| 8 | 0.02 s | not measured |
| 64 | 0.02 s | 11.7 ms median |
| 238 | 0.10 s | 42.7 ms median |
| 1,000 | 1.57 s | 513.6 ms median |
| 1,779 | 6.55 s | rejected |

At the 64-path threshold the two mechanisms are indistinguishable at this
resolution. Above it, parameters cost more, and both are far outside the budget
at closure scale. The collapse is the answer either way.

## Non-UTF-8 names

A file name containing byte `0xFF` cannot be created on this volume: `OSError: [Errno 92] Illegal byte sequence`. The parameter mechanism would carry the
bytes, but the file system refuses the name before the sandbox is involved. The
renderer can therefore require UTF-8 paths without losing a case the host
supports.

## Consequence

The renderer emits `(param "P<n>")` in place of every path and returns the
parameter vector beside the text. The helper calls
`sandbox_init_with_parameters`, and readiness checks that symbol rather than
`sandbox_init`. Escape logic disappears from the renderer. The tag is not
covered by this probe: `(with message ...)` was not given a parameter, so tag
handling stays a separate decision.

## Caveats

- Single runs, and `/usr/bin/time` resolves 10 ms. The threshold comparison is
  coarse on purpose; the implementation's own benchmark should use 30 runs.
- Values were distinct 45-byte strings, not real store paths. Path length moves
  the profile-text ceiling, not the cost at the 64-path threshold.
