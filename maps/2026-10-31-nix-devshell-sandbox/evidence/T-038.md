# T-038: setns into the sandbox's cgroup namespace

**Question.** Can an unprivileged same-uid process join the cgroup namespace of
a bwrap sandbox, so a command shares all seven namespaces rather than six?

**Method.** Start a holder with `--unshare-cgroup` as in T-033. Read the
holder's cgroup namespace inode. Enter it with `nsenter -t <pid> -U -C
--preserve-credentials`, and read `/proc/self/ns/cgroup` from the joined
process. Reproduce with `evidence/T-033-039-probes.sh`.

**Observation.**

```
holder: cgroup:[4026534410]
joined: cgroup:[4026534410]
cgroup namespace joined: yes
```

**Conclusion.** Yes. The join is refused for a different uid and needs no
capability beyond what the namespace owner already holds, the same model as
T-013. A command shares all seven namespaces, and the record carries seven
inodes.
