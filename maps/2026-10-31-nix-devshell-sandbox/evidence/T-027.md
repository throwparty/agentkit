# T-027: where does a provisioning kind live?

**Question.** Should a kind be a variant of the contract's closed
`ProvisionKind` enum, or live in a compiled-in registry outside the contract?

**Method.** Read the prototype findings, the implemented contract, and every
call site that branches on a kind.

## Observation

`adrs/2026-11-07-devshell-environment/findings.md:23-44` measures both shapes.
The prototype's `Step` carries `kind: String` and `parse_step` is its only
branch on the kind. Nothing after preparation sees the kind: `launch` receives
an environment, a list of mounts and a command, and would be identical for any
kind that produced the same contributions.

The crate branches on the kind at:

| Site | What it does |
| --- | --- |
| `crates/agentkit-litterbox/src/sandbox/contract.rs:74` | `ProvisionKind` is a closed enum |
| `crates/agentkit-litterbox/src/sandbox/contract.rs:117` | `ProvisionStep` is a closed enum with inline settings |
| `crates/agentkit-litterbox/src/provision/resolve.rs:263` | `step()` matches every variant to clone it |
| `crates/agentkit-litterbox/src/backends/docker/backend.rs:322` | `run_steps` destructures every variant |
| `crates/agentkit-litterbox/src/orchestrator/service.rs:552` | `command_step_refusal` matches the command variant |
| `crates/agentkit-litterbox/src/config.rs:701` and `testing.rs` | tests construct the variants |

The closed enum was a deliberate choice in
`adrs/2026-11-05-sandbox-provisioning/plan.md:128`: a runtime registry would
hide what a binary can actually apply, and the capture ADR was expected to need
a compile-time match. The prototype removes the second reason, because
preparation happens on the host and the launcher never learns the kind. The
first reason survives only as a statement about compilation, which a registry
table in the crate still gives.

## Conclusion

A compiled-in registry outside the contract. A step carries `identity`, `kind`
and the settings that kind owns, and the backend receives the contributions
instead of the step. The kind set stays compiled in, so `backends` and the
doctor can report what a binary contains, but adding a kind no longer changes
the contract. The contract changes only when a kind needs a contribution sort
the contract cannot express.
