# T-055. Do SBPL message, mach and network positions accept parameters?

Answer: yes. `sandbox_init_with_parameters` accepts a parameter in the deny
message, in `(global-name ...)` and in `(remote ip ...)`, so every dynamic
string in the profile can be a parameter and the renderer never escapes one.

Host: macOS 27.2.1 (26B131), arm64. Probed 2026-11-14.

## Reproduce

`T-055-params-scalars.c` applies one profile that uses a parameter in each
position:

```
(deny default (with message (param "TAG")))
(allow mach-lookup
  (global-name (param "M0"))
  (global-name (param "M1")))
(allow network-outbound
  (remote ip (param "N0")))
```

Values: tag `litterbox-t055 with spaces`, two `com.apple.*` service names, and
`localhost:8765`.

```
cc -O1 -o build/params-scalars T-055-params-scalars.c
build/params-scalars <workspace>
```

## Observation

```
applied
exit=0
```

All three positions accept a parameter. Combined with T-054, which covers
`(subpath ...)` and `(literal ...)` with a path containing `"` and `(`, every
value the renderer emits can travel out of band.

## Consequence

- The tag, mach services and loopback endpoints are parameters, not escaped
  text.
- The renderer has no escaper at all. Its only validation is that a path has no
  NUL and the tag and service names match their character rules, which keeps the
  log query and the service table sane rather than protecting the syntax.
- The `Loopback` posture can name `localhost:<port>` through a parameter, which
  is the shape the proxy ADR needs.

## Caveats

- The probe does not test a parameter inside `(target ...)` or `(extension ...)`;
  the backend emits neither.
- Parameter values are still C strings: NUL is impossible, and a value is not
  length-checked by the caller beyond the protocol's 64 KiB per string.
