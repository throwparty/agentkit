# T-015: does the devShell work on aarch64-darwin?

**Question.** Can the nix devShell evaluate and build on `aarch64-darwin`, so a
macOS CI job reuses the same `nix develop ./nix` wrapper as every other job?

**Method.** Citation from the Darwin spike, which was run on the target
platform.

- `adrs/2026-10-31-darwin-app-sandbox/findings.md:3` records the host as
  "macOS 27.2 (26B123), Apple silicon, SDK 27.2".
- The same file's reproduce block (lines 9-13) invokes every prototype through
  `nix develop ./nix --command …`, and `poc/results/t-009-custom.md:9` records
  the actual run: `nix develop ./nix --command ./poc/run.sh ./poc/custom/target/release/sandbox-custom custom custom`.
- The prototypes themselves were built with `cargo build --release` under that
  shell, so the devShell supplied a working Rust toolchain, linker and SDK
  discovery on the host.

The author of that ADR confirms it was written on a Darwin machine.

**Conclusion.** Yes. The flake evaluates and the devShell builds on
`aarch64-darwin`; the macOS CI job can wrap `nix develop ./nix` exactly as the
Ubuntu job does, and needs no narrower toolchain.

**Qualification.** This establishes the devShell, not the whole workspace's test
suite: only the Litterbox crate and the spike prototypes were built there. A
macOS job that runs `cargo test --locked` across the workspace would be the
first time the other crates (dbus-backed credentials, switchboard, tackle) are
compiled on Darwin, and nothing here predicts that. Selecting test packages or
test targets, as the contract design does, keeps that surface small.
