# T-010: per-sandbox resource limits

**Question.** Can per-sandbox resource limits be applied without a long-lived supervisor?

**Method.** `adrs/2026-10-31-linux-bwrap-lifecycle/poc/limits.sh` on NixOS with a systemd user manager.

**Observation.** The harness ran under a transient user scope. With `MemoryMax=64M` and `MemorySwapMax=0`, an 8 MiB allocation succeeded as a below-limit control and a 256 MiB allocation was OOM-killed by the scope (`Result=oom-kill`). With `TasksMax=16` alone, four threads succeeded as a control and a 64-thread workload was refused with the workload's own `thread-limit` error. The host stayed responsive.

Each probe checks the mechanism, not just a non-zero exit: the memory probe requires the scope's `Result=oom-kill`, and the task probe requires the workload's `thread-limit` error. A scope that fails to start fails the probe instead of passing it. The process-group fallback has no limits.

**Conclusion.** Yes on systemd hosts, through transient scope properties. The fallback runs unlimited.
