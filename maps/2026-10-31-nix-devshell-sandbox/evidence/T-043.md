# T-043. Can Seatbelt confine a sandbox with no Nix and no devShell?

Answer: yes. A `deny default` profile whose only inputs are a workspace and a
platform baseline confines a command with no Nix store grant and no devShell
contribution. The mechanism does not need Nix; a devShell is an optional extra.

Host: macOS 27.2.1 (26B131), arm64. Probed 2026-11-14.

## Reproduce

Sources sit beside this file: `T-043-helper.c` and `T-043-probe.sh`. The script
builds into `evidence/build/` and resets it on each run.

```
bash T-043-probe.sh
```

The helper resolves every path with `realpath`, renders a profile, applies it
with `sandbox_init(profile, 0, &error)`, and `execvp`s the command with the
environment it inherited. It exits 70 if the profile cannot be applied (never
execs unconfined) and 126 if exec fails.

Harness environment (`env -i`):

```
PATH=/usr/bin:/bin:/usr/sbin:/sbin HOME=<workspace> TMPDIR=<workspace>/tmp
LANG=C.UTF-8 USER=<user>
```

The profile is `deny default` plus: `process-exec`, `process-fork`,
`process-info*`/`signal` to the same sandbox, `file-read*` over `literal "/"`,
the platform baseline, the workspace and any `--read`, unqualified
`file-read-metadata`, `file-write*` over `/dev/null`, the workspace and any
`--write`, `sysctl-read`, and the twelve prototype `mach-lookup` names. The full
profile is 1538 bytes and contains no `/nix` (`grep -c nix` = 0).

## Checks

| # | Command | Result |
|---|---|---|
| 1 | `/bin/sh -c 'echo standalone-ok'` | `standalone-ok`, exit 0 |
| 2 | `echo inside > $HOME/inside.txt` | `inside`, exit 0 |
| 3 | `echo tmp > $TMPDIR/t.txt` | `tmp`, exit 0 |
| 4 | `echo nope > /tmp/t043-outside` | `Operation not permitted`, exit 1, file absent |
| 5 | `cat <ungranted dir>/id_ed25519` (readable outside) | `Operation not permitted`, exit 1 |
| 6 | exec `$(command -v nix)`, a `/nix/store` binary | dyld abort, exit 134 |

Check 6 verbatim:

```
dyld[89376]: Library not loaded: /nix/store/2s3mmjpp070rwn4p925af74hzvkln5sh-nix-util-2.35.6/lib/libnixutil.2.35.6.dylib
  Referenced from: <CCA62473-B491-3EE0-A141-90A5E794A9FF> /nix/store/g2n4lw86lg8xa3kml84hmynm22kla7j5-nix-2.35.6/bin/nix
  Reason: tried: '/nix/store/2s3mmjpp070rwn4p925af74hzvkln5sh-nix-util-2.35.6/lib/libnixutil.2.35.6.dylib' (file system sandbox blocked open())
exit=134
```

This is the decisive negative control. The Nix binary is present on the host and
runnable without the sandbox, and fails inside only because its store path is
not granted. So a sandbox with no store grant is confined, not merely broken.

## What the baseline needs

`(literal "/")` is required: deleting that one rule reproduces the
prototype's silent failure. The command aborts with SIGABRT (exit 134) and
prints nothing, which is why the prototype's findings call it out. With it, the
platform baseline above is sufficient for `/bin/sh`, coreutils and writes under
the workspace.

`file-read-metadata` unqualified was used here. The prototype scopes metadata to
the baseline, the grants and their ancestors; the narrower form is not needed
for this ticket, but a production profile should keep the narrower scope so
metadata does not become a directory-listing oracle over the whole filesystem.

The developer directory in the baseline is provisional; T-046 asks whether it is
a platform path or a toolchain contribution.

## Caveats

- `deny default` plus a baseline that omits the path denies an out-of-workspace
  read. The credential-shaped deny list is a separate policy layer and is not
  exercised here.
- The `mach-lookup` list is copied from one workload on one host. It was not
  minimised for this probe; it is data, not a constant.
- A `getcwd` warning appears when the harness runs from a directory outside the
  baseline. It is the sandbox doing its job, not a harness fault. The checks
  ran with the working directory at `/`.
- Check 6 shows an abort, not a clean EPERM. dyld dies because it cannot load
  the store dylib. A tool that has to run from the store must receive the
  closure as read grants (T-044 covers the scale).

## Source

Full source: `T-043-helper.c` beside this file. Excerpt:

```c
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

extern int sandbox_init(const char *profile, unsigned long long flags,
                        char **errorbuf);

static const char *BASELINE[] = {
    "/usr/bin", "/usr/lib", "/usr/share", "/usr/libexec",
    "/System/Library", "/System/Applications",
    "/Library/Developer", "/Applications/Xcode.app/Contents/Developer",
    "/Library/Frameworks", "/bin", "/sbin", "/private/etc",
    "/private/var/db/dyld", "/private/var/select", "/dev",
};
/* MACH[]: twelve com.apple.* names from the prototype's policy.rs. */

static char *must_realpath(const char *path) {
    char *resolved = realpath(path, NULL);
    if (!resolved) { perror(path); exit(70); }
    return resolved;
}

int main(int argc, char **argv) {
    /* parse --workspace/--read/--write/--dump-profile then -- command */
    /* realpath each input, build the profile with open_memstream */
    char *error = NULL;
    if (sandbox_init(profile, 0, &error) != 0) {
        fprintf(stderr, "sandbox_init: %s\n", error ? error : "unknown error");
        return 70;
    }
    execvp(command[0], command);
    return 126;
}
```
