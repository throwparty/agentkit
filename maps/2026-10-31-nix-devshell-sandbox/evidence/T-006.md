# T-006: virtualisation

**Question.** Do either of the chosen mechanisms require a separate kernel?

**Method.** The bwrap README's namespace description and the Darwin spike's stated scope.

**Observation.** bwrap uses the kernel's user, mount, pid, ipc, uts and cgroup namespaces and a mount table; the sandboxed process runs on the host kernel.

The Darwin spec lists as an explicit non-goal:

> Raising the isolation ceiling above the shared kernel: a kernel exploit escapes the sandbox

**Conclusion.** Both mechanisms confine in user space on the shared kernel, with no VM and no image. The security boundary is the kernel's own, so a kernel exploit defeats either.
