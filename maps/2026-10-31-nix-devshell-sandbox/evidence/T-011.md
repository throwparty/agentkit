# T-011: can the devShell capture supply the environment allowlist?

**Question.** Can the host-side capture of a devShell produce the environment
allowlist a sandbox needs, and is the naive capture safe?

**Method.** Three captures on the host, in this repository:

```bash
nix print-dev-env ./nix --json                          > devenv.json
nix develop ./nix --command sh -c 'env -0 > post.nul'    # after the shellHook
env -0                                                  > caller.nul
```

**Observation.**

`print-dev-env --json` emits `{bashFunctions, variables}`: **153 variables and
109 bash functions**. Each variable is tagged `exported`, `var` or `array`. Only
85 are exported with a non-empty value — the rest are stdenv build-phase state
(`outputDev`, `fixupOutputHooks`, `envBuildBuildHooks`, `initialPath`, …) that a
sandbox has no use for and that would be actively wrong to inherit.

`nix develop --command env -0` emits **270 records**, because it is the
devShell's environment *on top of the caller's entire session*:

```
only in the post-hook capture (selection):
  SSH_AUTH_SOCK, BITWARDEN_SSH_AUTH_SOCK, GNUPGHOME, DOCKER_HOST,
  DBUS_SESSION_BUS_ADDRESS, XDG_RUNTIME_DIR, WAYLAND_DISPLAY, DISPLAY,
  NIRI_SOCKET, OPENCODE_*, ATUIN_*, TMUX_*, EDITOR, PAGER, LESSKEYIN_SYSTEM
```

Two further problems with that capture:

1. **It is contaminated.** The devShell's `shellHook` prints version banners to
   stdout, and `env -0` writes to the same stdout, so one record's *name* came
   out as the whole banner ("From commonTools:\\n just 1.51.0 …"). The dump must
   go to a file or a spare fd.
1. **It is a credential leak.** Copying it into a sandbox hands the workload the
   SSH agent socket, the Bitwarden agent socket, the session D-Bus socket, the
   Wayland socket and `DOCKER_HOST` — each a path straight out of the
   confinement.

### The differential must cover overrides, not only additions

The `shellHook` does not just add variables; it **modifies** ones the stdenv
baseline already sets. `nix/flake.nix:232` prepends `$CARGO_HOME/bin` to `PATH`,
and a capture that only takes variables *absent* from the base silently drops
that, losing discovery of anything installed there. Comparing every post-hook
variable against the base value — or against the caller when the base does not
set it — gives the true set:

```
base exported: 85   hook additions+overrides: 16   total: 91

  ADDED      CARGO_HOME
  ADDED      NIX_GCROOT
  ADDED      RUSTFLAGS
  ADDED      RUSTUP_HOME
  OVERRIDDEN PATH           (now /home/…/agentkit/.cargo/bin:<devshell PATH>)
  OVERRIDDEN NIX_LDFLAGS    (now -rpath …nix-shell-env/lib …)
  OVERRIDDEN NIX_BUILD_TOP  (now the workspace)
  OVERRIDDEN XDG_DATA_DIRS
  OVERRIDDEN HOME, TMPDIR, TMP, TEMP, TEMPDIR   (noise: the provider overrides these)
  OVERRIDDEN SHLVL, _, out                      (noise: shell state and eval artefacts)
```

Six of the sixteen are real environment the workload needs; five are values the
sandbox must override anyway; three are noise.

**Conclusion.** Yes, but only by a differential capture that takes **additions
and overrides**: every exported variable from `nix print-dev-env --json`, then
for each variable after the hook, the post-hook value whenever it differs from
the base (or caller) value. Never copy `nix develop`'s environment wholesale.

Limits recorded:

- **Bash functions are lost.** 109 of them exist in the devShell and cannot be
  expressed as environment variables. Compilers and `cargo` do not need them;
  `genericBuild`, `stdenv` phases and any recipe that calls `buildPhase` do.
- **`HOME` and `TMPDIR` come from the devShell as `/homeless-shelter` and
  `/build`.** Both are wrong inside a sandbox and must be overridden by the
  provider.
- **Path-valued variables are absolute host paths.** `CARGO_HOME` and
  `RUSTUP_HOME` point into the checkout and `PATH` begins with a directory
  inside it, so the workspace is either bound at its host path or those
  references are rewritten. Only references to the *workspace* move; `/nix/store`
  is mounted at its own path, so store paths stay valid. T-016 binds at the host
  path.
- The capture is a snapshot. A devShell whose hook reads the network or the
  clock produces different values on each run; that is a property of the
  project, not of the capture.
