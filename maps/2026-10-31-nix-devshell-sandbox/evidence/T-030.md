# T-030: which variables cross into the sandbox?

**Question.** Should the step contribute the entered environment minus a
denylist of shell and Nix variables, or follow nix-direnv's rule for what the
development shell changes?

**Method.** Read nix-direnv 3.2.0, then reproduce its import step against this
repository's cached profile.

## The algorithm

`/nix/store/7p4ay46q9vmp8ph7sp90nfp75yz0h9gq-nix-direnv-3.2.0/share/nix-direnv/direnvrc:169-201`:

1. `values_to_restore` at `:172-179` saves `NIX_BUILD_TOP`, `TMP`, `TMPDIR`,
   `TEMP`, `TEMPDIR` and `terminfo`.
2. `:187` evaluates the `print-dev-env` script in the current shell.
3. `:197-201` restores each saved value, or unsets it when it was unset.

Nothing else is special-cased. The script does not assign `HOME`, `PWD`,
`OLDPWD`, `SHLVL` or `_`; a normal shell already has them, so they are unchanged
and never become part of the development shell's contribution.

## Reproduction

```bash
env -i HOME="$HOME" PATH=/run/current-system/sw/bin bash -c '
  declare -A before after
  while IFS= read -r -d "" kv; do before["${kv%%=*}"]=1; done < <(env -0)
  . .direnv/flake-profile-*.rc >/dev/null 2>&1
  while IFS= read -r -d "" kv; do after["${kv%%=*}"]=1; done < <(env -0)
  for k in "${!after[@]}"; do
    [ -z "${before[$k]+x}" ] && echo "$k"
  done | sort
'
```

The script adds 101 names in this checkout. They include the 18 empty
build-phase variables, `PATH`'s replacement value, `CARGO_HOME`, `RUSTUP_HOME`,
`RUSTFLAGS` and the `NIX_*` set. They also include the six temp variables, which
direnv restores.

`HOME`, `PWD` and `SHLVL` are present before evaluation and unchanged, so they
do not appear in the added set. `OLDPWD` did appear here because `bash -c` had
not set it before the evaluation. In a normal shell it is already set and
unchanged. The capture harness must start from the shell variables a real shell
has, or it will report them as contributions.

## Conclusion

Follow the direnv rule. Evaluate the `print-dev-env` script once in a sanitised
bash so the hook runs once, then restore `NIX_BUILD_TOP`, `TMP`, `TMPDIR`,
`TEMP`, `TEMPDIR` and `terminfo`. Everything else the evaluation changes is the
contribution. `HOME`, `PWD`, `OLDPWD`, `SHLVL` and `_` never enter it because
the caller already has them, and the sandbox backend supplies its own values.

This replaces the prototype's denylist of `PWD`, `OLDPWD`, `SHLVL`, `_`, `HOME`,
`TMPDIR`, `TMP`, `TEMP` and `TEMPDIR`. No path from the caller's home or the
host's temporary directory can cross, because neither is assigned by the script.
