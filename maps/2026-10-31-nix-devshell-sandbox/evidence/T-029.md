# T-029: are exported-but-empty variables contributed?

**Question.** Should the exported-but-empty build-phase variables that
`print-dev-env` reports be contributed to the sandbox, or dropped?

**Method.** List the exported-empty names in the baseline, then check which of
them survive into the entered development shell.

```bash
nix print-dev-env ./nix --json \
  | jq -r '.variables | to_entries[]
      | select(.value.type == "exported" and ((.value.value // "") == ""))
      | .key' \
  | sort
```

19 names:

```
cmakeFlags
configureFlags
depsBuildBuild
depsBuildBuildPropagated
depsBuildTarget
depsBuildTargetPropagated
depsHostHost
depsHostHostPropagated
depsTargetTarget
depsTargetTargetPropagated
doCheck
doInstallCheck
mesonFlags
OLDPWD
patches
propagatedBuildInputs
propagatedNativeBuildInputs
strictDeps
__structuredAttrs
```

The entered shell is measured with:

```bash
env -i HOME="$HOME" PATH=/run/current-system/sw/bin \
  nix develop ./nix --command sh -c 'env' \
  | cut -d= -f1 | sort
```

18 of the 19 are present and exported, with empty values. `OLDPWD` is the
exception and is shell state rather than a build-phase variable.

## Why they exist

They are `stdenv.mkDerivation` defaults, declared as empty lists or false and
serialised into the derivation environment:

- `pkgs/stdenv/generic/make-derivation.nix:395` `depsBuildBuild ? [ ]`
- `:402` `depsHostHost ? [ ]`
- `:416` `configureFlags ? [ ]`
- `:421` `doCheck ? doCheckByDefault`
- `:428` `strictDeps ? defaultStrictDeps`
- `:445` `patches ? [ ]`
- `:453` and `:942` `__structuredAttrs ? structuredAttrsByDefault`
- `:925` `cmakeFlags ? [ ]`

The paths are from the pinned nixpkgs input at
`.direnv/flake-inputs/ghycfvk55414f3acs5hw0pbx6xzs410i-source/`.

## What direnv does

nix-direnv 3.2.0 evaluates the whole `print-dev-env` script at
`/nix/store/7p4ay46q9vmp8ph7sp90nfp75yz0h9gq-nix-direnv-3.2.0/share/nix-direnv/direnvrc:187`
and restores only the six temp variables at `:197-201`. It does not unset the
empty build-phase variables, so they remain exported after `use flake`.

## Conclusion

Contributed. `nix develop` and `direnv` both leave them exported, so dropping
them diverges from the development shell. The difference is observable: under
`set -u`, `${patches}` fails when the variable is unset and succeeds when it is
empty. The prototype findings recorded 11; this checkout has 18. The evidence
file corrects the count.
