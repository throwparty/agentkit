# T-008: unprivileged user namespaces on the target hosts

**Question.** Do the target distributions permit unprivileged user namespaces?

**Method.** NixOS VM test (`adrs/2026-10-31-linux-bwrap-sandbox/poc/vm/default.nix`), Ubuntu 24.04 and Fedora 44 cloud VMs (`poc/vm/cloud/launch.sh`), and the Linux spike's harness.

**Observation.** NixOS, kernel 7.2.12: `unshare -U true` exits 0, bwrap runs. A NixOS guest with `user.max_user_namespaces=0` fails both; the enabled guest runs both and neutralises a setuid binary.

Ubuntu 24.04.5, kernel 6.8.0-147, bwrap 0.9.0:

| Configuration | `unshare -U` / bwrap as `ubuntu` | Setuid euid host / sandbox |
|---|---|---|
| `userns=off`, AppArmor restriction on | both fail with `EPERM` | 0 / sandbox unavailable |
| `userns=on`, restriction off | both succeed | 0 / 1000 |

Fedora 44, kernel 6.19.10, SELinux Enforcing, bwrap 0.12.0: `unshare -U`, bwrap and `--proc` succeed as the unprivileged user; a setuid helper prints 0 on the host and 1000 in the sandbox.

**Conclusion.** The host permits unprivileged user namespaces on NixOS, and on Ubuntu only when `kernel.unprivileged_userns_clone` is 1 and `kernel.apparmor_restrict_unprivileged_userns` is 0. Fedora permits them with SELinux enforcing. A host that restricts namespaces makes sandbox creation fail closed.
