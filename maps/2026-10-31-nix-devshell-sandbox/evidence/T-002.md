# T-002: the sandbox_init entry point on unsigned binaries

**Question.** Does the `sandbox_init` entry point confine an unsigned binary with a Seatbelt profile on a current macOS?

**Method.** `adrs/2026-10-31-darwin-app-sandbox/poc/results/t-005-apply.md`, `acceptance.md` and `t-009-custom.md` from the Darwin spike (macOS 27.2, Apple silicon).

**Observation.** The built helper was adhoc-signed with no TeamIdentifier:

```
Signature=adhoc
TeamIdentifier=not set
```

Confinement from that binary:

```
inside-ok
touch: /private/tmp/outside.txt: Operation not permitted
outside-denied
```

`acceptance.md` records `AC-011 | Applies unsigned | poc/results/t-005-apply.md | proven`. `t-009-custom.md` records `cargo build`, `cargo test` and `cargo run` succeeding, with `write-outside`, `write-home`, `read-ssh-key`, `read-keychain`, `connect` and `child-write` all reported as denied and a negative control reporting leaks without the sandbox.

**Conclusion.** `sandbox_init` applies a Seatbelt profile and confines unsigned binaries on macOS 27.2. This demonstrates the entry point, not the entitlement-based App Sandbox policy. Other macOS versions were not tested. `sandbox_init` remains deprecated.
