# T-007: lifecycle without a supervisor

**Question.** Can pause, resume and destroy work without a daemon or supervisor process?

**Method.** `adrs/2026-10-31-darwin-app-sandbox/poc/results/t-013-lifecycle.md` from the Darwin spike, which exercised process-level lifecycle on a sandbox with no supervisor.

**Observation.** The result table:

| Check | Custom | Nono |
|---|---|---|
| pid is its own process-group leader | yes | yes |
| pause (SIGSTOP to the group) freezes the loop | yes | yes |
| resume (SIGCONT) continues | yes | yes |
| delete (SIGKILL to the group) | gone, 0 survivors by sentinel | gone, 0 survivors |
| process that calls `setsid` survives the group kill | yes, 1 survivor | yes, 1 survivor |

The notes record that a `setsid` survivor "is still confined — the sandbox is inherited and cannot be dropped — but it can no longer be addressed by process group".

A process that calls `setsid` leaves the process group. The group kill reports zero survivors by the group sentinel, but the `setsid` child survives. It remains confined and cannot drop the sandbox, but it keeps running after destroy: it can consume CPU and write to paths the view grants.

**Conclusion.** Process groups provide group-local lifecycle only. They pause, resume and kill processes that stay in the group. Complete lifecycle support for arbitrary descendants is unresolved; a supervisor, cgroup, or process-tree tracker is required to stop a child that leaves the group. The map carries that as an unresolved item.
