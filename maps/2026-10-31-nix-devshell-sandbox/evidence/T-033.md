# T-033: the host sleep as the holder command

**Question.** Can the host's `sleep` hold pid 1 of a bwrap sandbox for an
effectively unbounded time, once bound into the view?

**Method.** NixOS, kernel 7.2.15, bubblewrap 0.12.0. The sandbox was started
with `--unshare-user --unshare-pid --unshare-ipc --unshare-uts --unshare-cgroup
--unshare-net --disable-userns --clearenv`, a PATH of
`/run/current-system/sw/bin`, the store, the system profile and `/etc` bound
read-only, a private proc, dev and tmpfs, and a host directory bound at `/src`.
The command was `sleep 2147483647`, a duration of about 68 years.

Reproduce with `evidence/T-033-039-probes.sh`.

**Observation.**

```
status document after: 26ms
view usable after: 60ms
holder alive: yes
holder cmdline: ... -- sleep 2147483647
```

**Conclusion.** Yes. The host `sleep` accepts a large integer duration and
holds the sandbox. The backend needs no GNU `infinity` spelling, so nothing in
the holder command depends on coreutils beyond a POSIX argument.
