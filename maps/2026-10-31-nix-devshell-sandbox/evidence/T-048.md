# T-048. Readiness without confining the caller

Answer: yes, by symbol lookup plus a functional probe process. `dlsym`
finds `sandbox_init` on this host, but only applying a profile proves the
mechanism still works, and that must happen in a child. The probe costs about
7.5 ms, cheap enough for startup.

Host: macOS 27.2.1 (26B131), arm64. Probed 2026-11-14.

## Reproduce

```
cc -O1 -o build/probe T-048-probe.c
./probe symbol
./probe apply
./probe invalid
./probe time 30
```

## Results

```
dlsym(RTLD_DEFAULT,"sandbox_init")=0x19d54a6bc
dlopen(libSystem)=0x377db8d10 dlsym(handle,"sandbox_init")=0x19d54a6bc
exit=0
```

The symbol is present, and `#include <sandbox.h>` still compiles against this
SDK (with a deprecation warning).

```
$ ./probe apply
applied
exit=0
```

The probe child applied `(version 1)(deny default)` and exited without exec.

```
$ ./probe invalid
sandbox initialization failed: unbound variable: nonsense at <input string>, line 2, column 7
sandbox_init: unbound variable: nonsense at <input string>, line 2, column 7
exit=70
```

The failure is a message, not an errno, and the helper maps it to a non-zero
exit. A readiness check that only tested the symbol would report available here
and be wrong.

```
$ ./probe time 30
runs=30 median_ms=7.550 p95_ms=8.350 min_ms=7.047 max_ms=8.766
```

The parent was unaffected by every probe: after the 30 runs it read
`<probes>/t047-secret/lib` (`secret`) and wrote `/tmp/t048-parent`. The profile
never touches the process that calls readiness.

## Consequence for D

- Readiness has two checks: `dlsym(RTLD_DEFAULT, "sandbox_init")` is non-null,
  and a probe child applies a minimal profile and exits 0. Report `Unavailable`
  with the `sandbox_init` message as the reason if either fails.
- The probe must be a child process; applying in the server would confine the
  server. That is the same constraint as exec, and T-049 measured the fork side.
- The probe's profile should be the smallest thing that proves application, not
  a real sandbox profile: `(version 1)(deny default)` is enough.
- This catches the case the symbol cannot: an OS that keeps the symbol but
  stops enforcing, or starts rejecting profiles. Such a change is exactly the
  `sandbox_init` longevity risk the prototype named.
