## Blockers

1. **FR-024's copy-on-write ancestor edits contradict non-goal 10 and have no implementation path** (unfixed residual of review.1 item 20). FR-024: "ancestor edits are copy-on-write with provenance recorded"; non-goal 10: "no copy-on-write editing exists in v1". `schema.sql` reserves `copiedFrom` in `turns.metadata` (line 43) with no producer, and no ACP method, requirement, or task performs an ancestor edit. Delete the clause and the metadata key, or specify the mechanism — as written the storage layer carries dead schema for a feature the spec forbids.
2. **Project-layer `[mcp_servers.*]` is accepted by the config of record but trusted nowhere.** `config.example.toml` (line 46): "MCP servers (both layers…)". FR-013 connects servers from "client-provided mcpServers and user configuration" — no project layer. FR-022 trust-gates "project scripts, personas, actors, and prompts" — no mcp_servers. T-003 rejects only "endpoint and credential fields" at project level. A stdio server entry is arbitrary command spawn (argv plus env) executed at session start; a cloned repo declaring one is the exact Scout-1 compromise channel the trust gate exists for. Decide: reject `[mcp_servers.*]` in project config the way endpoints are rejected, or add it to the trust-gated set. Blocks T-003's rejection semantics and T-018's connection source.
3. **FR-026, FR-027 — and task T-036 — belong to no milestone.** The plan's approach says each of the ten milestones "closes a named set of spec requirements"; the milestone FR lists cover FR-001…FR-025 except FR-026 and FR-027. T-035 (agent invocation) and T-031 (config options) exist but are claimed by no milestone, and T-036 (HTTP transport, FR-001's second half) is likewise unassigned. Partially fixed residual of review.1 item 3: the tasks exist, the schedule doesn't.

## Inconsistencies between documents

4. **Collision handling is specified two different ways.** FR-009: "collisions within a namespace (two prompts with one name across layers) resolve by precedence with the project layer winning". Plan invokables component and T-021: "collisions are configuration errors at load". Both cannot be the registry's behaviour. If the intent is cross-layer → precedence, same-layer → error, neither document says so.
5. **"Rename rules" persist in the plan's mcp component** ("duplicate-name precedence and rename rules", plan line 154 / plan.toon line 33) while FR-009 now says namespacing makes cross-server collisions impossible and FR-013 specifies precedence plus first-turn reporting — no rename anywhere. The rule is defined nowhere and T-018 tests only precedence. Residual of review.1 item 10: delete the phrase or define it.
6. **Direct-invocation syntax: the plan still says `!name`** in three places (M6 approach, invokables component, dataFlow) against `/!name` in FR-011, AC-006, EC-007, EC-008, and T-024. Residual of review.1 item 6 — spec and tasks were normalised, the plan was not.
7. **`session/delete` capability placement disagrees.** FR-002 advertises "sessionCapabilities for list close and resume, session/delete" (delete outside the map); T-010 advertises "sessionCapabilities for list close resume delete" (delete inside). One of them misstates the ACP capability map — check the SDK and align.
8. **T-015's stub note contradicts its own dependency list.** Description: "tool-call integration against the registry and pipeline lands here (T-021, T-022) — until then the loop tests against stubs"; dependencies include T-021 and T-022. If they are prerequisites, "until then" never occurs. Either the loop is buildable against stubs (drop the dependency edges, keep the integration note) or it is not (drop the stub sentence). This decides whether M4 is independently testable, which the plan's approach claims every milestone is.

## Gaps — required behaviour with no owner

9. **No task ships the `/compact` prompt definition.** FR-018 requires "the manual path defines a complete /compact turn"; T-028 implements interception of compaction-tagged prompts, but the tagged prompt asset itself appears in neither builtins inventory (plan architecture item 13, builtins component) nor any task. The summariser actor has the same problem: documented in `scripts-api.md` and the builtins component, but shipped by no task (T-029 tests titling, doesn't ship the actor).
10. **MCP tool-result truncation has no test.** FR-013 truncates at the same 16 KiB limit as direct invocation; T-024 tests the direct path, T-018's criteria (connect, hang, failure, duplicate, first-turn status) omit truncation.
11. **Lease surfacing in `session/list` is untested.** FR-004: "ownership lease with heartbeat surfaced in session/list"; T-011's criteria cover ordering, filtering, and ephemeral marking; T-033 tests contention errors, not list surfacing.
12. **Missing-credentials → ACP authentication flow has no task.** FR-021 requires it; T-030 tests first-run with empty config but not the auth path, and T-014 tests the helper itself. Also verify the ACP v1 surface actually exposes an authentication flow — the requirement leans on Quest F4 without naming the method.

## Ambiguities to settle before implementation

13. **"Live" ephemeral forks vs fire-and-forget.** FR-016 defines live as "from fork_session until await_completion returns or times out", but the shipped `provision-sandbox.rhai` never awaits — its fork stays live forever, permanently consuming the live-fork budget. Either liveness ends when the fork's turn completes, or the example violates the budget model it illustrates.
14. **Permission-request timeout ownership is undefined.** FR-014: "request timeouts are reject-once" — who times out (harness or client) and after how long is unstated. Related: T-022 tests "headless auto-reject", a behaviour the spec does not define — the ask fallback asks regardless of the interactive indicator, so headless rejection must emerge from cancel/timeout, not an auto-reject rule.
15. **`title_trigger` firing cadence is undefined.** The payload carries `turns_since_title`, implying a harness-side schedule; nothing says what fires the event or how often.
16. **"Summaries are treated as untrusted content" (FR-018)** has no mechanical consequence — no role, marker, or delimiter is specified, and nothing tests it (Scout finding 9 asked for exactly this).
17. **"Script-driven model calls are surfaced in the client" (FR-016)** — by what notification? Notice, agent message, and tool card are three different user experiences; pick one.
18. **`first_retained_turn_id` semantics across nested compactions are implicit.** Traced: with `c2.fr` pointing below an intervening compaction `c1`, the CTE silently re-elides — `c2`'s claim to keep the older turn verbatim is not honoured, `c1`'s summary stands in. Graceful degradation for input that shouldn't occur, but T-007's property tests should constrain `fr` generation (or the schema comment should state the invariant) so the behaviour is deliberate.
19. **"Truncation-to-hash" for oversized script arguments** (plan scripts component) is an undefined term — presumably the payload is replaced by a digest so scripts can detect but not read oversized arguments. One sentence would fix it. Relatedly, FR-011 restricts direct invocation to MCP tools but never says what `/!prompt.x` or `/!agent.x` returns (FR-026 makes agent invokables model-invokable only, so presumably a precise error — say so).
