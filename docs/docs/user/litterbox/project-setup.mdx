# 📂 Setting up your project

Create `.agentkit/litterbox/config.toml` in your repository:

```toml
[project]
# Optional: override the default project slug (derived from directory name)
# slug = "my-project"
setup-command = "busybox httpd -h /src -p 0.0.0.0:8080"

[[ports]]
name = "www"
target = 8080
```

The sandbox's image is not a project setting: it belongs to the person running
the code, in the untracked `.agentkit/litterbox/config.local.toml`:

```toml
backend = "docker"

[backends.docker]
# Pin by digest where possible: the image is the confinement boundary.
image = "busybox@sha256:..." # or a tag you are willing to have change
```

The setup command only runs when the person running the code allows it. Cloning a
repository is not consent to execute its shell command. Grant one repository by
adding the namespace `litterbox list` prints to `allowed-projects` in the local
override:

```toml
allowed-projects = ["my-project-1a2b3c4d"]
```

`allow-project-setup = true` is the machine-wide alternative: it permits the
setup command of every repository, including ones you have not seen yet. Use it
deliberately, not to unblock a single project.

For details on what configuration options are available, see the [configuration
reference](reference/config) and [backends](backends).

When a new sandbox is created, Litterbox will:

- Create a new branch named after the sandbox in your Git repository.
- Materialise the source code at the sandbox's workspace path.
- Run the setup command to start the HTTP server.
- Assign it a random host port that forwards to the HTTP server running on port
  8080 in the sandbox.
