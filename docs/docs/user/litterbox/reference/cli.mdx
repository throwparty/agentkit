# 👩‍💻 Command line interface

## Global options

- `--backend <BACKEND>` Select the backend for this invocation instead of the configured one

## `backends`

Report the backends available on this machine, their readiness and their capabilities

Options:

- `--json` Emit structured JSON instead of a table

## `delete`

Delete a sandbox

Arguments:

- `NAME` Name of the sandbox to delete

Options:

- `-f, --force` Delete even if the sandbox is active

## `doctor`

Report whether this project can create a sandbox on this machine

Options:

- `--json` Emit structured JSON instead of a table

## `list`

List all sandboxes in the current repository

## `pause`

Pause one or more sandboxes

Arguments:

- `[NAME]` Sandbox name to pause

Options:

- `--all` Pause all sandboxes in this repository
- `--machine` Pause all Litterbox sandboxes on this machine

## `resume`

Resume a paused sandbox

Arguments:

- `NAME` Name of the sandbox to resume

## `shell`

Execute a command in a sandbox

Arguments:

- `NAME` Name of the sandbox to run the command in
- `COMMAND` Command and arguments to execute

## `stdio`

Run the MCP (Model Control Protocol) server over stdio

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | success |
| 1 | failed |
| 2 | usage |
| 3 | not found |
| 4 | conflict |
| 5 | unsupported |
| 6 | denied |
| 7 | unavailable |


## Sandbox lifecycle

A sandbox is `active`, `paused` or `missing`. `active` and `paused` are derived from the
sandbox's compute; `missing` means the record and the branch exist but the compute has
exited. Every command that takes a sandbox expects `active`.

### Commands

| Command | `active` | `paused` | `missing` |
| --- | --- | --- | --- |
| `list` | reported as `active` | reported as `paused` | reported as `missing`; the listing exits 0 |
| `shell` | runs the command | blocks until the sandbox is resumed | exits 3, not found |
| `pause` | freezes the sandbox | succeeds, changing nothing | exits 3, not found |
| `resume` | succeeds, changing nothing | thaws the sandbox | exits 3, not found |
| `delete` | refused without `--force` | removes the record and the branch | removes the record and the branch |

Creating a sandbox is only available over MCP. There is no `create` command.

:::warning Paused sandboxes accept no work

A command sent to a paused sandbox joins its frozen cgroup, so it does not run and does
not return until the sandbox is resumed. Resume the sandbox first.

:::

See [Sandbox lifecycle](../lifecycle) for the state diagram, the failure classes and how to recover a missing sandbox.
