# 👩‍💻 Command line interface

## Global options

- `--backend <BACKEND>` Select the backend for this invocation instead of the configured one

## `backends`

Report the backends available on this machine, their readiness and their capabilities

Options:

- `--json` Emit structured JSON instead of a table

## `delete`

Delete a sandbox

Arguments:

- `NAME` Name of the sandbox to delete

Options:

- `--ignore-running` Delete even if the sandbox's compute is running
- `--ignore-invalid` Delete even if the record or its compute cannot be read
- `--ignore-unmerged` Delete even if the sandbox branch, resolution or staging workspace may hold work the shared branch does not

## `doctor`

Report whether this project can create a sandbox on this machine

Options:

- `--json` Emit structured JSON instead of a table

## `list`

List all sandboxes in the current repository

## `pause`

Pause one or more sandboxes

Arguments:

- `[NAME]` Sandbox name to pause

Options:

- `--all` Pause all sandboxes in this repository
- `--machine` Pause all Litterbox sandboxes on this machine

## `reconcile`

Stage or finish a merge with a rewritten sandbox branch

Arguments:

- `NAME` Name of the sandbox to reconcile

Options:

- `--finish` Land the merge commit on the branch
- `--abort` Remove the staging worktree and leave the branch
- `--json` Emit structured JSON instead of a table

## `remote`

Add the Git remote that holds this project's sandbox branches

Arguments:

- `[NAME]` Name for the remote

## `resume`

Resume a paused sandbox

Arguments:

- `NAME` Name of the sandbox to resume

## `shell`

Execute a command in a sandbox

Arguments:

- `NAME` Name of the sandbox to run the command in
- `COMMAND` Command and arguments to execute

## `status`

Report how a sandbox's branch and workspace diverged

Arguments:

- `NAME` Name of the sandbox to report

Options:

- `--json` Emit structured JSON instead of a table

## `stdio`

Run the MCP (Model Control Protocol) server over stdio

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | success |
| 1 | failed |
| 2 | usage |
| 3 | not found |
| 4 | conflict |
| 5 | unsupported |
| 6 | denied |
| 7 | unavailable |


## Sandbox lifecycle

A sandbox has a compute state and a source state. The compute state is `active`,
`paused` or `missing`; it describes the process. The source state is `clean`,
`diverged` or `resolving`; it describes the branches. `diverged` means the shared
branch advance is held because the branch moved under unsaved work or the shared tip
carries a conflict. `resolving` means a `sandbox-reconcile` resolution is open.
Neither source state refuses a tool: only the branch advance waits.

### Commands by compute state

| Command | `active` | `paused` | `missing` |
| --- | --- | --- | --- |
| `list` | reported as `active` | reported as `paused` | reported as `missing`; the listing exits 0 |
| `shell` | runs the command | exits 4, `conflict`, and names the resume command | repairs the sandbox from the sandbox branch, warns on stderr, then runs the command |
| `pause` | freezes the sandbox | succeeds, changing nothing | exits 3, not found |
| `resume` | succeeds, changing nothing | thaws the sandbox | exits 3, not found |
| `status` | reports the source state | reports the source state | reports the source state; a repair is not attempted |
| `reconcile` | stages, finishes or aborts the host merge | unchanged; it does not join | unchanged |
| `delete` | refused without `--ignore-running` | removes the record and branches; `--ignore-unmerged` when work would be lost | removes the record and branches; `--ignore-unmerged` when work would be lost |

### Commands by source state

| Command | `clean` | `diverged` | `resolving` |
| --- | --- | --- | --- |
| `list` | `clean` | `diverged` | `resolving` |
| `shell` | runs; a snapshot advances the shared branch | runs; a snapshot stays on the sandbox branch | runs; edits are the resolution |
| `pause`, `resume` | compute only; the source state is unchanged | unchanged | unchanged |
| `status` | clean | diverged, with the reason | resolving, with the conflicts |
| `delete` | no unmerged flag | `--ignore-unmerged` | `--ignore-unmerged` |

Creating a sandbox is only available over MCP. There is no `create` command.

A missing sandbox is repaired on the next command that needs live compute. If the
workspace is gone, repair materialises the sandbox branch first and reports
`source: sandbox`. When that branch is absent it falls back to the shared branch and
reports `source: shared` with the missing ref. An open resolution whose sandbox
branch is gone is refused with the recorded `synced`/`ours` and the Git or jj
recovery; `status` prints the same continuation with `sandbox absent`.

`delete` has one flag per guard: `--ignore-running` for live compute,
`--ignore-invalid` for a record or status that cannot be read, and
`--ignore-unmerged` for a sandbox branch, resolution or staging workspace that may
hold work the shared branch does not. A refusal names every flag the record needs;
a flag whose condition does not hold is reported as unused.

See [Sandbox lifecycle](../lifecycle) for the state diagram, the failure classes and how to recover a missing sandbox.
