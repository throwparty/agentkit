# 🔧 Providers

Tackle talks to endpoints exposing the OpenAI chat-completions API — an OpenAI-compatible server, or a proxy standing in front of another API. Anthropic's Messages API and OpenAI's Responses API are not spoken directly; front them with a translating proxy (see [Examples](#examples)). Each endpoint is a named block in your configuration; models are addressed as `endpoint-name/model`.

:::tip

See [the configuration reference](../reference/config.mdx) for where to place configuration.

:::

## Endpoints

Each endpoint declares where to send model traffic, which wire format to speak, and how to authenticate:

```toml
[endpoints.local]
base_url = "http://localhost:11434/v1"
wire_format = "openai-chat-completions"
auth = "none"

[defaults]
model = "local/llama-3.2"
```

- `wire_format`, currently only `openai-chat-completions` .
- `auth`, determines how credentials for the session are sourced:
  - `none`: no credentials sent.
  - `helper`: bearer token sourced from a credential helper at request time.
- `models`: an optional static list used as a fallback when `/models` discovery fails or returns nothing.

Model discovery fetches the endpoint's `/models` list at session start; discovered models are offered alongside your static fallbacks in the model selector.

## Credentials

For endpoints that need their own bearer token, set `auth = "helper"` and name a credential helper:

```toml
credential_helper = "keychain"

[endpoints.rogue]
base_url = "https://rogue.example.com"
wire_format = "openai-chat-completions"
auth = "helper"
```

At request time Tackle resolves the endpoint's bearer token through the named helper and reads `access_token` from its JSON output. Store the token with [`tackle auth`](../reference/cli#auth), which writes through that same helper:

```bash
tackle auth add rogue sk-...
```

`tackle auth status` reports which identities resolve. If the credential can't be resolved, the endpoint isn't removed — it's advertised through ACP's `authMethods` and the `authenticate` method, so your harness can prompt for login instead of failing at first prompt.

## Examples

An OpenAI-compatible local runtime:

```toml
[endpoints.local]
base_url = "http://localhost:11434/v1"
wire_format = "openai-chat-completions"
auth = "none"
```

An Anthropic or OpenAI Responses endpoint can be fronted by an OpenAI-compatible proxy — for example, [Switchboard](../../switchboard/providers), which fronts your OpenAI, Anthropic, and local subscriptions, translates their APIs to the chat-completions shape, and handles their credentials itself, leaving Tackle nothing to authenticate:

```toml
[endpoints.switchboard]
base_url = "http://localhost:3812/openai/v1"
wire_format = "openai-chat-completions"
auth = "none"
models = []

[defaults]
model = "switchboard/claude-sonnet-4-5"
```

With Switchboard running (`switchboard --config switchboard.toml`), this is all the configuration Tackle needs — models are discovered from the proxy's `/models` list, and the switchboard-qualified names flow through unchanged.

## Checking it works

Start Tackle and begin a session; the model selector lists each configured endpoint's models, qualified by endpoint name. Pick one and send a prompt — if the endpoint is unreachable you'll see the failure classified in the turn's result rather than a hang.
