# 🔳 OpenCode

OpenCode serves models through two independent products. Configure only the one you use.

| Product          | Billing         | Base URL                        |
| ---------------- | --------------- | ------------------------------- |
| **OpenCode Zen** | `pay_as_you_go` | `https://opencode.ai/zen/v1`    |
| **OpenCode Go**  | `subscription`  | `https://opencode.ai/zen/go/v1` |

## OpenCode Zen

The [OpenCode Zen](https://opencode.ai/docs/zen/) gateway serves several model families across three wire formats under a single base URL and API key. Because a Switchboard provider is pinned to one `api_surface`, Zen is configured as three provider blocks sharing the same `base_url` and credential.

Free models are limited to the OpenCode client and are not available through Switchboard.

| Identity        | `api_surface`             | Model families                    |
| --------------- | ------------------------- | --------------------------------- |
| `zen_chat`      | `openai-chat-completions` | DeepSeek, GLM, Kimi, MiniMax      |
| `zen_responses` | `openai-responses`        | GPT, Grok, Muse                   |
| `zen_messages`  | `anthropic-messages`      | Claude, Qwen Plus                 |

Claude and Qwen Plus use the `anthropic-messages` surface; native Anthropic support is on the [roadmap](../roadmap).

```toml
[[providers]]
identity = "zen_chat"
api_surface = "openai-chat-completions"
base_url = "https://opencode.ai/zen/v1"
billing = "pay_as_you_go"
models = [
  "deepseek-v4-flash",
  "deepseek-v4-flash-free",
  "glm-5.2",
  "glm-5.3-flash",
  "kimi-k3",
  "minimax-m3",
  "qwen3.8-max",
]

[providers.auth]
type = "bearer_token"

[providers.pricing]
input_per_mtok = 0
output_per_mtok = 0

[[providers]]
identity = "zen_responses"
api_surface = "openai-responses"
base_url = "https://opencode.ai/zen/v1"
billing = "pay_as_you_go"
models = [
  "gpt-5.4",
  "gpt-5.5",
  "gpt-5.6-luna",
  "grok-4.6",
  "muse-spark-1.3",
]

[providers.auth]

[providers.pricing]
input_per_mtok = 0
output_per_mtok = 0

[[providers]]
identity = "zen_messages"
api_surface = "anthropic-messages"
base_url = "https://opencode.ai/zen/v1"
billing = "pay_as_you_go"
models = [
  "claude-haiku-4-5",

input_per_mtok = 0
```

The model lists above are a representative subset — Zen's catalogue churns, and the full lists are long.

### Zen credentials

Zen draws on workspace credits. Store an OpenCode Console API key under each identity:

```shell
switchboard auth add zen_chat oc_sk_...
switchboard auth add zen_responses oc_sk_...
switchboard auth add zen_messages oc_sk_...
```

The key must be allowed to request models, not just list them.

### Regenerating the Zen model list

The authoritative source for Zen model families is the models.dev catalog, classified by the SDK package each model declares (`providers.opencode.models[*].provider.npm`), intersected with what `https://opencode.ai/zen/v1/models` serves right now. The script rebuilds all three `models` lists from both:

<details>
    <summary>Regenerating the Zen model list</summary>

```bash
#!/usr/bin/env bash
# Generate OpenCode Zen [[providers]] blocks for switchboard config.toml.
# Surface: models.dev providers.opencode.models[*].provider.npm
# Membership: GET https://opencode.ai/zen/v1/models
#
# Usage: opencode-zen-models.sh >> ~/.config/agentkit/switchboard/config.toml
set -euo pipefail

MODELS_DEV_URL="${MODELS_DEV_URL:-https://models.dev/api.json}"
ZEN_MODELS_URL="${ZEN_MODELS_URL:-https://opencode.ai/zen/v1/models}"

tmpdir="$(mktemp -d)"
trap 'rm -rf "$tmpdir"' EXIT

curl -fsSL "$MODELS_DEV_URL" -o "$tmpdir/models.dev.json"
curl -fsSL "$ZEN_MODELS_URL" -o "$tmpdir/zen-models.json"

# model ids live on zen /models, classified by models.dev provider.npm
#   @ai-sdk/openai    -> openai-responses
#   @ai-sdk/anthropic -> anthropic-messages
#   null / missing    -> openai-chat-completions
#   anything else     -> skip (google, systemone, unknown)
jq -r --slurpfile live "$tmpdir/zen-models.json" '
  ($live[0].data | map(.id) | unique) as $live_ids
  | .opencode.models
  | to_entries
  | map(select(.key as $id | $live_ids | index($id)))
  | map(
      .key as $id
      | (.value.provider.npm // null) as $npm
      | {
          id: $id,
          surface: (
            if $npm == "@ai-sdk/openai" then "openai-responses"
            elif $npm == "@ai-sdk/anthropic" then "anthropic-messages"
            elif $npm == null then "openai-chat-completions"
            else empty
            end
          ),
        }
    )
  | group_by(.surface)
  | map({ key: .[0].surface, value: map(.id) | sort })
  | from_entries
' "$tmpdir/models.dev.json" > "$tmpdir/by-surface.json"

emit_provider() {
  local identity="$1" surface="$2"
  local models
  models="$(jq -r --arg s "$surface" '.[$s] // [] | .[]' "$tmpdir/by-surface.json")"
  if [ -z "$models" ]; then
    echo "error: no models for $identity ($surface)" >&2
    exit 1
  fi

  echo '[[providers]]'
  echo "identity = \"$identity\""
  echo "api_surface = \"$surface\""
  echo 'base_url = "https://opencode.ai/zen/v1"'
  echo 'billing = "pay_as_you_go"'
  echo 'models = ['
  printf '  "%s",\n' $models
  echo ']'
  echo
  echo '[providers.auth]'
  echo 'type = "bearer_token"'
  echo
  echo '[providers.pricing]'
  echo 'input_per_mtok = 0'
  echo 'output_per_mtok = 0'
  echo
}

emit_provider zen_chat openai-chat-completions
emit_provider zen_responses openai-responses
emit_provider zen_messages anthropic-messages
```

</details>

The generated blocks are ready to use; make sure they replace (rather than duplicate) existing Zen blocks.

## OpenCode Go

[OpenCode Go](https://opencode.ai/docs/go/) is the subscription counterpart: a smaller, curated set of coding models with monthly included usage. Because the allowance is quotaed rather than billed per token, all three provider blocks use `billing = "subscription"`.

Go serves the same three wire formats as Zen, but has no Gemini surface in Switchboard. `gemini-4-argon` is in Go's catalogue; the script below skips it because Switchboard has no Gemini client.

| Identity       | `api_surface`             | Model families                                                            |
| -------------- | ------------------------- | ------------------------------------------------------------------------- |
| `go_chat`      | `openai-chat-completions` | DeepSeek, GLM, Kimi, MiMo, MiniMax, LongCat, Step, Hy, and `-free` models |
| `go_responses` | `openai-responses`        | GPT Luna, Grok, Muse Spark Contributor                                    |
| `go_messages`  | `anthropic-messages`      | Claude Haiku, MiniMax M3, Qwen                                            |

Claude Haiku uses the `anthropic-messages` surface; native Anthropic support is on the [roadmap](../roadmap).

### Go credentials

Go requires a workspace subscribed to Go. Store an OpenCode Console API key under each identity:

```shell
switchboard auth add go_chat oc_sk_...
switchboard auth add go_responses oc_sk_...
switchboard auth add go_messages oc_sk_...
```

The key must be allowed to request models, not just list them. Go Teams members use a personal key; service account keys are not covered by Go Teams.
