# 🔧 Providers

Each provider is a `[[providers]]` block in your Switchboard configuration, declaring where requests go, which wire format to speak, how to authenticate, and what they cost. Configured blocks are grouped by vendor:

- [OpenAI](openai) — the ChatGPT subscription via the Codex API, and platform API keys
- [OpenCode](opencode) — the Zen gateway, serving several model families across three wire formats
- [Ollama](ollama) — local models, no credentials

Field-by-field documentation for every key in a provider block lives in the [configuration reference](../reference/config).

## Mutation scripts

Providers can attach [mutation scripts](../reference/config#mutations) that rewrite every outbound request — headers and body — just before it is forwarded.

```rhai
// scripts/custom-header.rhai
fn mutate(request) {
    request.headers["x-custom-header"] = "custom-value";
    request
}
```

```toml
mutations = ["scripts/custom-header.rhai"]
```

This is useful when a provider expects something your client does not send — for example, OpenCode's Zen gateway requires an `x-opencode-session` header shaped like a session id before it will serve `-free` models. See the [OpenCode provider page](opencode) for a full configuration.

Scripts run in declaration order, in a sandbox, before the provider credential is injected. An invalid header or a script error fails the request: nothing is forwarded unmutated.

## Starting the proxy

```shell
switchboard --config switchboard.toml
```

The HTTP server starts on `127.0.0.1:3812` by default. The session database is created at `~/.switchboard/sessions.db`.

## Checking it works

```shell
curl http://127.0.0.1:3812/openai/v1/models
```

This returns provider-qualified model ids plus combined bare aliases where the shape is unambiguous. Once you see models, you're ready to [configure your agent](../agents/opencode) to point at Switchboard.
